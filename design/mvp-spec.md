# redoCebiv MVP仕様書

最終更新: 2026-03-18
バージョン: 0.1（初稿）

---

## 前提

- 機能の単位: **ユースケース単位**（「タスクを追加する」「ログインする」など、ユーザーの行動目標1つ）
- 対応スタック: Next.js / React / TypeScript / Tailwind（初期対応）
- 入力方式: ZIPアップロード（GitHub連携は後回し）

---

## 1. 機能要件

### UC-01: プロジェクトをアップロードする

**概要**: ユーザーが自分の Next.js / React アプリのZIPファイルをアップロードし、解析可能な状態にする。

**アクター**: ユーザー（非エンジニア〜初級者）

**事前条件**: ユーザーがログイン済みである

**基本フロー**:
1. ユーザーがホーム画面の「プロジェクトを追加」ボタンを押す
2. ZIPファイル選択ダイアログが開く
3. ユーザーがZIPを選択してアップロード
4. システムがZIPを展開し、ファイル構造を解析する
5. AIがコードを解析し、ユースケース候補を抽出する
6. プロジェクト詳細画面に遷移し、ユースケース一覧が表示される

**例外・エラー**:
- ZIPが20MBを超える → エラー「ファイルサイズの上限は20MBです（node_modulesを除いてZIP化してください）」
- Next.js/Reactプロジェクトとして認識できない → 警告「対応形式ではない可能性があります」（続行は可能）
- 解析タイムアウト（60秒超） → エラー「解析に失敗しました。再試行してください」

**出力**:
- プロジェクトオブジェクト（id・名前・ファイル構造・ユースケース一覧）

---

### UC-02: ユースケースを選んで機能トレースを見る

**概要**: ユーザーが「タスクを追加する」などのユースケースを選ぶと、そのユースケースに関連するファイル・処理フロー・日本語説明が表示される。

**アクター**: ユーザー

**事前条件**: プロジェクトがアップロード済みで、ユースケース一覧が表示されている

**基本フロー**:
1. ユーザーがプロジェクト詳細画面でユースケースを選択する
2. システムが対象ユースケースに関連するファイルをAIで特定する
3. 機能トレース画面が表示される：
   - 関連ファイル一覧（ファイル名・役割の説明）
   - 処理フロー（入力 → 分岐 → 状態更新 → 表示更新）
   - 日本語のやさしい説明
4. ユーザーがファイルをクリックすると、該当コード箇所が強調表示される

**例外・エラー**:
- 関連ファイルが特定できない → 「このユースケースに関するコードを特定できませんでした」

**出力**:
- 関連ファイルリスト（パス・役割・主要な行番号）
- 処理フロー（ステップのリスト）
- 日本語説明テキスト

---

### UC-03: 変更候補を調べる

**概要**: ユーザーが「ボタン文言を変えたい」「未入力なら保存できないようにしたい」などの意図を入力すると、変更すべきファイルと場所・理由が提示される。

**アクター**: ユーザー

**事前条件**: プロジェクトがアップロード済み

**基本フロー**:
1. ユーザーがプロジェクト詳細画面で「変更を調べる」を選択
2. テキストフィールドに変更意図を日本語で入力する（例: 「保存ボタンのテキストを『登録』に変えたい」）
3. AIが変更候補を生成する
4. 変更候補画面に以下が表示される：
   - 変更タイプ（文言変更 / 条件変更 / バリデーション追加 / 表示変更）
   - 変更すべきファイル（パス・行番号・コード断片）
   - なぜそこを変えるのかの理由
   - 難易度感（★☆☆ / ★★☆ / ★★★）

**例外・エラー**:
- 意図が曖昧で候補が絞れない → 「もう少し具体的に教えてください」と再入力を促す

**出力**:
- 変更候補リスト（ファイル・場所・理由・変更タイプ・難易度）

---

### UC-04: ミニ改造課題に取り組む

**概要**: 現在のコードベースに対してシステムが軽い変更課題を出す。ユーザーは「どのファイルのどこを変えるべきか」を予想して回答する。

**アクター**: ユーザー

**事前条件**: プロジェクトがアップロード済み

**基本フロー**:
1. ユーザーがプロジェクト詳細画面で「課題に取り組む」を選択、または成長画面から「次の課題」を選ぶ
2. システムがユーザーの成長レベルに合った課題を1つ表示する
   - 課題タイプ: 文言変更 / 条件追加 / バリデーション追加 / 表示変更
   - 例: 「未入力のまま追加ボタンを押せないようにしたい」
3. ユーザーが「変更すべきファイル」と「変更内容の予想」を入力する
   - ファイルはファイルツリーから選択
   - 変更内容は自由記述
4. ユーザーが「提出」を押す → UC-05 へ

**任意**: ヒントボタンを押すと部分的なヒントが表示される（成長判定に影響）

**例外・エラー**:
- 特になし（未回答で提出した場合は答え合わせのみ表示）

**出力**:
- ユーザーの回答（ファイル選択・変更内容テキスト）

---

### UC-05: 答え合わせと解説を見る

**概要**: 課題への回答後、正解のファイルと変更箇所・理由・変更タイプを確認できる。

**アクター**: ユーザー

**事前条件**: UC-04 で課題に回答済み

**基本フロー**:
1. システムがユーザーの回答と正解を比較する
2. 答え合わせ画面に以下が表示される：
   - 正解のファイル・行番号・変更内容
   - ユーザーの回答との差分（合っていた点・違った点）
   - なぜそこを変えるのかの解説
   - 変更の種類（UIテキスト / 条件分岐 / バリデーション / 表示ロジック）
   - 同種の変更が他にどこにあるか（応用例）
3. 成長トラッキングが更新される（自動）
4. 「次の課題へ」ボタンで UC-04 に戻れる

**成長判定ロジック**:
- ファイル正解 + 変更内容正解 + ヒントなし → 「自力でできた」
- ファイル正解 + ヒントあり → 「ヒントありでできた」
- ファイル不正解 → 「未達」

**出力**:
- 答え合わせ結果・解説テキスト・成長トラッキング更新

---

### UC-06: 成長トラッキングを確認する

**概要**: ユーザーが「読める / 当てられる / 直せる」の3軸でどこまで到達しているかを確認し、次に取り組むべき課題を知る。

**アクター**: ユーザー

**事前条件**: 少なくとも1つの課題に取り組んでいる

**基本フロー**:
1. ユーザーが成長画面に遷移する（ナビゲーションから常時アクセス可能）
2. 3軸の現在地が表示される：
   - 読める: 関連ファイル特定 / UIイベント追跡
   - 当てられる: 文言変更箇所 / 条件追加箇所
   - 直せる: UI軽微修正 / 簡単なバリデーション追加
3. 「今日できるようになったこと」が表示される
4. 直近の成長履歴が表示される（課題名・達成日・判定）
5. 「次におすすめの課題」が1〜3件表示される

**出力**:
- 3軸スコア（各項目: 未達 / ヒントありでできた / 自力でできた）
- 成長履歴リスト
- 推奨課題リスト

## 2. 非機能要件

### パフォーマンス

| 項目 | 目標値 | 備考 |
|---|---|---|
| ZIPアップロード + 初期解析 | 30秒以内 | タイムアウトは60秒 |
| ユースケース一覧の表示 | 解析完了後1秒以内 | |
| 機能トレース生成（AI） | 10秒以内 | ストリーミング表示を検討 |
| 変更候補生成（AI） | 10秒以内 | ストリーミング表示を検討 |
| 画面遷移（静的） | 1秒以内 | |

### セキュリティ

| 項目 | 方針 |
|---|---|
| アップロードコードの保持 | セッション中のみ（ログアウトまたは24時間で削除） |
| コードのサーバー外部送信 | AI処理のためのAPIリクエストのみ（外部保存なし） |
| ファイルサイズ上限 | 20MB（node_modules除外を案内） |
| 許可するZIPの内容 | テキストファイルのみ（バイナリ・実行ファイルは除外） |
| 認証 | 必須（メール認証 or OAuth） |

### 対応環境

| 項目 | 仕様 |
|---|---|
| 対応ブラウザ | Chrome最新・Safari最新・Firefox最新 |
| モバイル対応 | 読み取り専用操作はスマホでも可 / 課題回答はPC推奨 |
| 最小画面幅 | 375px（モバイル）/ 1024px（フル機能） |
| 言語 | 日本語（MVP）|

## 4. API仕様

### 共通

- Base URL: `/api`
- Content-Type: `application/json`
- 認証: セッションCookie（NextAuthなど）

**共通エラーレスポンス**:
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "エラーの説明"
  }
}
```

---

### POST /api/projects

ZIPをアップロードしてプロジェクトを作成・解析する。

**リクエスト**: `multipart/form-data`
```
file: <zipファイル>
name: string（任意、未指定時はZIPファイル名）
```

**レスポンス** `201 Created`:
```json
{
  "id": "proj_abc123",
  "name": "todo-app",
  "stack": ["next.js", "react", "typescript"],
  "status": "analyzing",
  "createdAt": "2026-03-18T10:00:00Z"
}
```

**エラー**:
- `400 FILE_TOO_LARGE`: 20MB超過
- `400 INVALID_FILE`: ZIPではない
- `422 UNSUPPORTED_STACK`: 対応スタックと判定できない（警告のみ、201を返す場合あり）

---

### GET /api/projects/:id/usecases

プロジェクトから抽出されたユースケース一覧を取得する。

**レスポンス** `200 OK`:
```json
{
  "projectId": "proj_abc123",
  "usecases": [
    {
      "id": "uc_001",
      "name": "タスクを追加する",
      "description": "ユーザーがテキストを入力してタスクを追加する",
      "relatedFiles": ["components/AddTaskForm.tsx", "hooks/useTaskForm.ts"],
      "status": "traced"
    },
    {
      "id": "uc_002",
      "name": "タスクを完了にする",
      "description": "チェックボックスをクリックしてタスクを完了状態にする",
      "relatedFiles": ["components/TaskItem.tsx", "store/taskStore.ts"],
      "status": "untraced"
    }
  ]
}
```

**エラー**:
- `404 PROJECT_NOT_FOUND`
- `202 STILL_ANALYZING`: 解析中（クライアントはポーリング）

---

## 付録: 画面遷移図

```
ホーム (/)
  ├── プロジェクト追加 → [ZIPアップロードモーダル] → プロジェクト詳細
  ├── プロジェクトカード → プロジェクト詳細 (/projects/[id])
  │     ├── トレースを見る → 機能トレース (/projects/[id]/trace/[ucId])
  │     │     └── 課題を出す → ミニ課題 (/projects/[id]/challenge/[id])
  │     ├── 変更を調べる → 変更候補 (/projects/[id]/change)
  │     │     └── この変更で課題を出す → ミニ課題
  │     └── 課題に取り組む → ミニ課題 (/projects/[id]/challenge/[id])
  │           └── 提出 → 答え合わせ（同画面内） → 次の課題
  └── 成長 → 成長ダッシュボード (/growth)
              └── 次の課題 → ミニ課題
```
