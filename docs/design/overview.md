# redoCebiv — プロダクト概要

最終更新: 2026-03-18

---

## 一言コピー

> AIが作ったコードを、機能から理解できるようにする

---

## このプロダクトが解く課題

vibe coding / AI支援開発の広がりにより、「AIに作らせてアプリはできたが、なぜそれが動いているのか分からない」というユーザーが増えている。

このプロダクトは、その状態から以下の状態へ導くことを目的とする：

- どのコードがその挙動を作っているかが分かる
- どこを変えれば仕様変更できるか見当がつく
- 軽い変更なら少しずつ自力でできる

---

## 想定ユーザー

### 最優先ターゲット
- 非エンジニア〜初級者
- Cursor / Copilot / Replit / Claude Code / v0 などで何かを作った
- React / Next.js / TypeScript 系の小規模アプリを持っている
- 文言変更・条件追加・簡単なバリデーション・表示変更で詰まる

### 次点ターゲット
- PM / デザイナー / Biz職で社内ツールや簡易アプリを作っている人
- 個人開発を始めたばかりの人

### MVPでは対象外
- すでに大半を自力で直せるエンジニア
- 大規模システムの熟練開発者

---

## コア価値（MVPで解く3課題）

1. 自分のアプリのどこを読めばいいか分からない
2. 少し仕様を変えたいが、どこを触ればいいか分からない
3. 理解が進んでいるのか、自分で実感できない

---

## 競合との差別化

**競合カテゴリ**: 生成系（Replit / Lovable / v0） / IDE内説明系（Copilot / Cursor） / 学習系 / 可視化系

**差別化ポイント**:
- 自分のAI生成物を教材化する
- 機能起点で読む順序に再構成する
- 変更箇所を予想させる
- 軽い改造を通じて理解を定着させる

**コアの体験設計**: `Predict → Locate → Edit → Observe → Explain`

---

## MVP機能

### 1. プロジェクト読み込み
- ZIPアップロード優先（GitHub連携は後回し）
- 対応スタック: Next.js / React / TypeScript / Tailwind

### 2. 機能トレース
- ユーザーが「この画面」「このボタン」「この機能」を選択
- 関係ファイル・処理フロー・日本語説明を表示
- 入力 → 分岐 → 状態更新 → 表示更新 の流れを可視化

### 3. 変更候補提示
- ユーザーが変更意図を入力（例：「未入力なら保存できないようにしたい」）
- 見るべきファイル・変更タイプ・難易度感を提示

### 4. ミニ改造課題
- 現コードベースに対して軽い変更課題を出す
- 例: ボタン文言変更・未入力ならボタン無効化・エラーメッセージ追加

### 5. 答え合わせと解説
- 変更すべき箇所・理由・他の候補・変更の種類を解説

### 6. 理解成長トラッキング
- 行動ベースで測定（知識スコアではない）
- 3軸: 読める / 当てられる / 直せる
- 各項目3段階: 未達 / ヒントありでできた / 自力でできた

## 画面構成

| 画面 | 内容 |
|---|---|
| ホーム | プロジェクト一覧・最近の成長・次の課題 |
| プロジェクト詳細 | 概要・主要機能一覧・最近見た機能 |
| 機能トレース | 選択機能・関連ファイル・処理フロー・説明 |
| 変更候補 | 変更意図の入力・候補ファイル・候補理由・難易度 |
| ミニ課題 | 課題・ヒント・提出・答え合わせ |
| 成長 | できるようになったこと・3軸到達度・直近履歴・次の課題 |

---

## MVPの最短体験フロー

1. プロジェクトをアップロード
2. 機能やボタンを選ぶ
3. 関係ファイルと処理フローが出る
4. 軽い仕様変更課題が出る
5. ユーザーが変更箇所を予想する
6. 正解と解説を見る
7. 成長トラッキングに反映される

## 料金プラン

| プラン | 内容 | 価格感 |
|---|---|---|
| Free | 1プロジェクト・月3解析・基本機能 | 無料 |
| Lite | 複数プロジェクト・深いトレース・課題・成長トラッキング | 月500〜700円台 |
| Team | 共有ワークスペース・理解マップ共有・引き継ぎ用途 | 要検討 |

**方針**: 個人はFree/Lite中心、高単価はTeamで回収。

---

## MVPでやらないこと

- IDEそのものになること
- コード生成そのもの
- PRレビュー機能
- 巨大リポジトリの高度解析
- 多言語・多フレームワーク対応
- 本格的チーム管理
- 本格的な総合スコア化

---

## 次に詰めるべき論点

1. MVPで扱う「機能」の単位（画面単位か・ボタン単位か・ユースケース単位か）
2. 最初に出すミニ課題タイプの優先順位
3. MVP仕様書への落とし込み（機能要件・非機能要件・画面要件・入出力仕様）
4. 画面ワイヤーの作成
5. Liteに入れる具体機能の精査
6. Team向け価値の具体化
