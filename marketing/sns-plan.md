## 1. プラットフォーム戦略

### プラットフォーム役割分担

| プラットフォーム | 役割 | 投稿頻度 | 優先度 |
|---|---|---|---|
| **X（旧Twitter）** | 日常的な認知獲得・共感・拡散 | 毎日1〜2本 | ★★★ |
| **Zenn** | 技術記事・深い説明・SEO | 月2〜3本 | ★★☆ |
| **note** | ストーリー・プロダクト開発日記 | 月1〜2本 | ★☆☆ |

### ターゲットペルソナ（SNS上での姿）

- Cursor / v0 / Claude Code でアプリを作った非エンジニア
- 「動いてるけど怖い」「触ると壊れそう」という不安を抱えている
- X では #vibe_coding / #個人開発 / #cursor などのタグを追っている
- Zenn や note で「AIで作った」系の記事を読んでいる

### X運用方針

- **語り口**: 同じ悩みを持つ人への共感ベース。説教しない・上から言わない
- **文体**: ですます不要、短く、ツッコミやすい
- **画像**: UI画面のスクショ・コード断片・シンプルな図解を積極活用
- **リプライ**: 関連ツイートに積極コメント（認知を広げる）

### Week 2: 教育ウィーク

**月曜（読み方 Tips #1）**
```
AI生成コードの読み方 ①

まずファイルを探すな。
「このボタン押したとき何が起きてほしいか」を先に言語化する。

例:「追加ボタン → タスクが増える」

この動作を起点にファイルを追うと
圧倒的に速く読める
```

**火曜（読み方 Tips #2）**
```
AI生成コードの読み方 ②

components/ フォルダのファイルは
「画面に見えるもの」を担当してることが多い

よく分からないコードでも
「これは見た目の担当だ」と分かるだけで
読む気がだいぶ変わる
```

**水曜（変え方 Tips #1）**
```
「ボタンのテキストを変えたい」ときに探す場所

1. そのボタンが属する画面のコンポーネントファイル
2. ファイル内で「保存」「登録」などのテキストをCmd+F
3. そこを書き換えるだけ

AIに聞かなくても変えられる変更って
実は結構ある
```

**木曜（変え方 Tips #2）**
```
バリデーション追加（未入力チェック）の場所の見つけ方

Reactの場合は大体こう：

ボタンコンポーネントの disabled={条件} を見る
→ 条件を管理してるhooksかstateを探す
→ そこに空チェックを追加

「どこを変えるか」さえ分かれば
実装はAIに任せていい
```

**金曜（まとめ Tips）**
```
自分のAI生成コードと仲良くなる3ステップ

① 機能を「動作」で言語化する
  「追加ボタン → タスクが増える」

② その動作に関係するファイルを1つ特定する

③ そのファイルを100行だけ読む

これを1週間繰り返すと
「触ると壊れそう」感がなくなってくる
```

**土曜（Zenn記事への誘導）**
```
「AI生成コードを自分で読む技術」について
もう少し詳しく書いた記事を公開しました

→ [Zenn記事URL]

Cursor / v0 / Claude Code で作った
React/Next.jsのアプリを想定して書いてます
```

**日曜（問い）**
```
コードが「読める」と「分かる」って違うと思う

読める = 文字として追える
分かる = なぜそこにそのコードがあるか、が腑に落ちる

たいてい後者だよね
```

## 3. 自動化フロー設計

### 推奨ツール構成（低コスト・日本語対応）

```
[コンテンツストック]
Googleスプレッドシート
  └── 投稿文・予定日・ステータス・プラットフォームを管理

      ↓ Make（旧Integromat）が週次でトリガー

[スケジューリング]
Buffer
  └── X / note への予約投稿
  └── 最適な時間帯に自動投稿

      ↓ 投稿完了

[分析]
Buffer Analytics / X Analytics
  └── エンゲージメント・フォロワー増減を週次確認
```

### Makeフロー詳細

**フロー1: スプレッドシート → Buffer 自動転送**

```
トリガー: 毎日 午前8時
  ↓
Googleスプレッドシートから「今日の投稿」を取得
  ↓
ステータスが「予約済み」かつ投稿日が今日のものをフィルタ
  ↓
Bufferに投稿をスケジュール（X: 12時 / 20時）
  ↓
スプレッドシートのステータスを「投稿済み」に更新
```

**フロー2（オプション）: Claude APIで投稿案を自動生成**

```
トリガー: 週1回（月曜 午前9時）
  ↓
その週のテーマをスプレッドシートから取得
  ↓
Claude APIに「テーマ×バイブコーダー向け×X投稿文×7本」を依頼
  ↓
生成された投稿案をスプレッドシートに追記（ステータス: 要確認）
  ↓
Slackに通知「今週の投稿案が届いています。確認してください」
  ↓
人が確認・修正 → ステータスを「予約済み」に変更 → フロー1が実行
```

### スプレッドシート構成

| 列 | 内容 |
|---|---|
| 投稿日 | YYYY-MM-DD |
| 曜日 | 月〜日 |
| 週テーマ | 共感 / 教育 / デモ / CTA |
| プラットフォーム | X / note / Zenn |
| 投稿文 | テキスト |
| 画像 | ファイルURL（任意） |
| ステータス | 草稿 / 要確認 / 予約済み / 投稿済み |
| 備考 | メモ |

### 推奨投稿時間（X / 日本）

| 時間帯 | 理由 |
|---|---|
| 7:30〜8:00 | 通勤前チェック |
| 12:00〜12:30 | ランチタイム |
| 20:00〜21:00 | 帰宅後・夜のリラックスタイム |
